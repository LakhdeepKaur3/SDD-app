# Todo app — Constitution

## Stack
- Frontend: Next.js 14 (App Router) with TypeScript
- React 18
- Tailwind CSS for styling
- Backend: Node.js with Express and TypeScript
- Prisma ORM for database access
- PostgreSQL for persistence
- Docker for running the backend and PostgreSQL
- Frontend and backend must live in separate folders: `frontend/` and `backend/`
- Frontend communicates with backend through REST APIs
- No localStorage for todo persistence
- No Next.js API routes

## Code organisation
- Frontend page lives in `frontend/app/page.tsx`
- Frontend components live in `frontend/app/components/`
- Frontend API helpers and shared types live in `frontend/lib/`
- Backend entry point lives in `backend/src/server.ts`
- Backend routes live in `backend/src/routes/`
- Backend controllers live in `backend/src/controllers/`
- Backend services live in `backend/src/services/`
- Prisma schema lives in `backend/prisma/schema.prisma`
- Components that use browser APIs or React client-side features declare `"use client"` at the top
- Database access must go through Prisma

## Styling conventions
- Tailwind utility classes only — no separate CSS files for layout
- `frontend/app/globals.css` contains only the three Tailwind directives
- Default Tailwind palette; no custom theme extension for this lab

## Data conventions
- Todos are objects: `{ id: string, text: string, completed: boolean, createdAt: string }`
- `createdAt` is an ISO 8601 string
- IDs are generated by Prisma/database, not the browser
- PostgreSQL is the source of truth for todos
- Database connection details must be stored in environment variables
- Frontend must not access the database directly

## API conventions
- `GET /api/todos` — get all todos
- `GET /api/todos/:id` — get a single todo
- `POST /api/todos` — create a todo
- `PUT /api/todos/:id` — update a todo
- `DELETE /api/todos/:id` — delete a todo
- API responses use JSON
- API errors use appropriate HTTP status codes

## Docker conventions
- PostgreSQL runs through Docker
- Backend connects to PostgreSQL using the configured database URL
- Database credentials must not be hardcoded

## UI conventions
- Single page, no routing
- Empty state when there are no tasks
- Newest task at the top of the list
- Completed tasks show a strikethrough; the row is not removed
- Show loading and error states for API operations
